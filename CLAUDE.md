# Somnya

An iOS app built and installed from the command line. `build.sh` is the entry
point — prefer it over raw `xcodebuild`, and never build by driving the Xcode GUI.

```
./build.sh              build, sign, install to the connected iPhone
./build.sh --no-install build and sign only (use this to check it compiles)
./build.sh --device <id> target a specific device
./build.sh -v           verbose xcodebuild output
```

The no-arg path leaves the app installed on the phone rather than stopping at a
`.app` in a build directory. Do not add a build-only default.

## Project layout

- **`project.yml` is the project.** The `.xcodeproj` is generated by xcodegen and
  gitignored. Edit `project.yml` and run `xcodegen generate` (build.sh does this
  for you). Never edit the `.xcodeproj` — the change is erased on the next build.
- **Sources are flat in `Sources/`.**
- **`Info.plist` lives at the repo root**, not inside `Sources/`. Inside `Sources/`
  it is handled as both the plist and a bundled resource, and that collision
  silently corrupted the built plist here once already — down to just the
  `UIBackgroundModes` array.

## Background audio

The `audio` background mode lets the mic keepalive persist with the screen
locked, which is what makes overnight tracking work. If launch breaks on a free
account, check that the provisioning profile still carries background-audio.

## Signing

`DEVELOPMENT_TEAM` lives in `Config.xcconfig`, which is **gitignored** because a
Team ID is machine-specific. `Config.xcconfig.example` is the committed template.
Never commit a real Team ID, and never hardcode one in `project.yml`.

Builds are signed with a personal Apple ID, so they stop opening after 7 days.
Re-running `./build.sh` renews them.

## Releases

`./release.sh` reads `MARKETING_VERSION` from `project.yml` — the single source of
truth — verifies the version builds, tags it, and publishes a GitHub release with
no attached binary. To release: bump the version there, commit, push, run it.

## build.sh is generated

`build.sh` comes from `walled_garden/_template/ios-build.sh`. A bug in it is a bug
in the template: fix it there and run `walled_garden/sync-build-scripts.sh`,
rather than patching this copy and letting the three projects drift apart again.
`sync-build-scripts.sh --check` reports drift without writing.

`release.sh` is *not* generated — the three copies have diverged, and the two
non-xcodegen projects read the version from a different file than this one.
